Read `web/docs/BUILD-GUIDE.md` first. Spec sources in `../Plan.md`: "SEO: ranking plan" sections 5 (Reviews on autopilot, On-site reviews), 9 (migration), 10 (Measuring it: admin SEO page, monthly report), "Admin panel" (SEO row).

`src/app/admin/(panel)/seo/**`, `src/components/admin/seo/**`, `src/lib/seo/{gsc,reviews,report}.ts`, `src/lib/admin/{seo,reviews}.ts`, `src/app/api/cron/search-console/route.ts`, `src/app/(site)/review/**` (the public review form), `src/components/reviews/**`, `tests/unit/seo-admin-*.test.ts`, `tests/db/seo-admin.test.ts`.

## Build (admin pages, actions and routes start with `requireRole()` from `@/lib/auth/session`; the redirects manager's delete is owner-only)
**Search Console client (`gsc.ts`).** Uses the `jose` library (installed) to sign a service-account JWT and call the Search Console API with `fetch` (`https://oauth2.googleapis.com/token`, then `POST https://searchconsole.googleapis.com/webmasters/v3/sites/<site>/searchAnalytics/query`); credentials from `GSC_SERVICE_ACCOUNT_JSON` (base64 JSON) and `GSC_SITE_URL` (`@/lib/env`). When not configured every function returns `{ configured: false }` and the UI shows a "Connect Search Console" card explaining the steps (verify the domain property by DNS, add the service account email as a user); no network calls. `GET /api/cron/search-console/` (bearer `CRON_SECRET`; skip with `{ skipped: true }` when unconfigured): pulls the last 3 days of query + page rows (clicks, impressions, ctr, position; row limit 5000) and upserts into `search_console_daily` (`ON CONFLICT (date, query, page)`). The query/response parsing and the upsert shaping are pure functions, unit-tested with fixture JSON.

**SEO page `/admin/seo/`** (tabs): **Overview**: clicks, impressions, average position for the **20 priority searches** (taken from `content/seo/keyword-map.json`: pick the first 20 listed `searches`; match them to `search_console_daily.query` case-insensitively), a trend chart (Recharts, text alternative), top pages, pages with errors/problems (derived from data you have: products failing the SEO checklist (import `evaluateSeoChecklist` and its types from `@/lib/admin/seo-checklist`: a contract stub owned by admin-products that throws until they implement it; catch that and show "—" so your page never crashes), pages `noindex`, hidden products still receiving redirects). **Products**: table of every product with its checklist score (green/amber/red) and which checks fail, linking to the editor `/admin/products/<id>/`. **Redirects**: manager over the `redirects` table (list with hits, from, to, status, reason; add manual 301/410; edit; delete is owner-only; validation prevents redirect loops and chains: a target must not itself be a source, and a source must start with `/`); every write calls `revalidateRedirects()` from `@/lib/revalidate`. **Reviews**: moderation queue (pending/approved/rejected), approve/reject/delete, link to the product, filter by verified visit; approving calls `revalidateReviews()`. **Review requests**: counts of review-request WhatsApp links sent (`bookings.reviewRequestedAt` and `invoices.reviewRequestedAt` not null) and the current rating/count from approved reviews. **Monthly report**: `src/lib/seo/report.ts` builds a report for a chosen month (rankings for the priority searches, clicks, new reviews, products below green, the next two guides due from the content calendar in `content/seo/keyword-map.json` clusters without a page yet) rendered on the page, with "Copy as text" and "Download CSV".

**On-site reviews.** Visitors who came in can review the product they bought. **Review links** (`src/lib/seo/reviews.ts`): `createReviewLink({ bookingId?, invoiceId?, productId })` returns `/review/<token>/`, a `jose` HS256 token (secret `AUTH_SECRET` or `CRON_SECRET`; clear error when neither is set) valid 60 days, carrying the ids; `verifyReviewToken`. Staff get the link from the admin (add a small server action `generateReviewLinkAction(productId, bookingId?)` plus a button on the Reviews tab: "Create a review link for a booking") and send it over WhatsApp. **Public form `/review/[token]/`** (`params` is a Promise; noindex): shows the product, star rating, optional title, review text (10–2000 chars), name (as shown publicly); Zod-validated server action; one review per token (reject duplicates by checking `reviews` for the same booking/invoice + product); inserts with `approved: false`, `verifiedVisit: true`, then a thank-you state ("It will appear after the team has checked it") and a bell notification (`review`, link `/admin/seo/?tab=reviews`). Product pages show stars and `aggregateRating` from approved reviews only (the product-page and seo-core agents read `reviews`; you only write them).

## Tests

DB: review submission (valid, duplicate, too short, expired/tampered token), moderation changes visibility, redirect CRUD, search_console upsert idempotence.
