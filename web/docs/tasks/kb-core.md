# Task: kb-core (knowledge base: parsing, chunking, indexing, retrieval, starter loader)

Read `web/docs/BUILD-GUIDE.md` first. Spec source in `../Plan.md`: "Knowledge files" (starter pack, Markdown format, JSON format, what happens on upload) and "Chatbot → What happens to each message" step 5 (Knowledge retrieval).

## You own
`src/lib/kb/**` (replace the contract stub `api.ts`: same exports; add `parse.ts`, `chunk.ts`, `index.ts`, `embeddings.ts`, `rank.ts`), `src/lib/seed/knowledge.ts` (replace the no-op), `tests/unit/kb-{parse,chunk,rank}.test.ts`, `tests/db/kb.test.ts`.

## Build
Schema: `kb_documents`, `kb_chunks` (generated `tsv` column, optional `embedding vector(N)` created only when embeddings are switched on), `faqs`, `synonyms` (`src/lib/db/schema/knowledge.ts`). Use `gray-matter` (installed) for front matter.

**Parsing (`parse.ts`, pure).** Markdown: front matter `{ title, tags: string[], priority: 'high'|'normal'|'low' }` validated with Zod; errors carry line numbers where possible (`{ line, message }`). JSON documents are either an FAQ array (`[{ q, alt?: string[], a, tags?: string[] }]`) or a synonyms object (`{ "l-shape": ["corner sofa", "sectional"] }`); detect by shape; validate with Zod and report the index/path of each bad entry. `slug` comes from the file name.

**Chunking (`chunk.ts`, pure).** Each `##` section becomes one chunk with its heading path ("Delivery › Delivery inside Colombo": document title › heading); sections over about 350 tokens (estimate tokens as `ceil(words * 1.3)`) split at paragraph/sentence boundaries with a 50-token overlap; chunks inherit the document tags and priority; the intro before the first `##` becomes a chunk titled with the document title. Deterministic output.

**Ingest (`index.ts`, exported as `ingestDocument`).** In one transaction: validate; compute a checksum; if an existing current document with the same slug has the same checksum return it unchanged; otherwise mark the old row `isCurrent = false` (versioned: keep it, its chunks are removed from search by `isCurrent`), insert version + 1 as current, store the original text (via `storage()` from `@/lib/storage`, key `kb/<slug>/v<version>.<ext>`; skip silently if storage fails), insert chunks (full-text vector is generated by the database), and for JSON FAQ files upsert rows in `faqs` (match on normalised question; keep `hitCount`; set `source` from the input) and for synonym files upsert `synonyms`. After writing call `revalidateTags('kb')` from `@/lib/revalidate` when running inside Next (wrap in try/catch: tests run outside Next). Return the `IngestResult` from the contract.

**Search (`searchKnowledge`).** Only chunks of enabled, current documents. Full-text: `websearch_to_tsquery('english', query)` ranked with `ts_rank`, headings weighted above body (the generated vector already weights A/B), optionally filtered by tags overlap; `priority: 'high'` breaks ties (small boost). When embeddings are enabled (`settings.chat.embeddings.enabled` and a vector column exists) also run a cosine search and merge the two rankings with reciprocal rank fusion (`rank.ts`, pure, k = 60). Return the top `limit` (default 3). Embeddings: `embeddings.ts` calls the OpenRouter embeddings endpoint (`POST https://openrouter.ai/api/v1/embeddings`, bearer `OPENROUTER_API_KEY`, model from `OPENROUTER_EMBED_MODEL` or settings) — a function `embedTexts(texts): Promise<number[][]>` that throws a clear error when not configured. `reindexAll()`: rebuild chunks from the stored current documents; when embeddings are enabled embed every chunk in batches of 32. Also export `enableEmbeddings(model)`: probes the model's dimension with a test string, runs `CREATE EXTENSION IF NOT EXISTS vector` and `ALTER TABLE kb_chunks ADD COLUMN IF NOT EXISTS embedding vector(<dim>)` plus an HNSW index (`vector_cosine_ops`), stores `settings.chat.embeddings`. The vector extension is available on Neon; on local PGlite the extension is not loaded by default, so make the code detect that and return a clear "not available locally" error instead of crashing. Do not edit migrations; run the DDL at enable time only.

**Starter loader (`src/lib/seed/knowledge.ts`, exported `seedKnowledge(db, log)`).** Reads every `content/knowledge/*.md`, `*.json` (skip names starting with `_` and `README`) and calls `ingestDocument` with `source: 'starter'`. It must be safe to run on every start: unchanged checksum is a no-op, and a starter document the admin edited (`editedInAdmin = true`) is never overwritten. `ensureSeeded` in `src/lib/seed/index.ts` already calls it once after the first seed (leave that file alone; the integrator will make the call idempotent per start if needed). Missing folder = no-op with a log line. The starter files are being written by other agents in parallel: write your tests with your own fixtures under `tests/fixtures/kb/`, not against `content/knowledge/`.

## Tests
Pure unit tests for parsing (valid, bad front matter, JSON shapes, error line numbers), chunking (heading path, long sections split with overlap, determinism), RRF. `tests/db/kb.test.ts`: ingest creates chunks and versions; same checksum is a no-op; edited text creates version 2 and hides version 1 from search; FAQ upsert keeps hit counts; search finds the right chunk, respects tags and disabled documents, ranks `high` priority first on ties; the loader tolerates an empty folder.
