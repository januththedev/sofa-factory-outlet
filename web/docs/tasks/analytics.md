# Task: analytics (tracking, rollups, Visitors page, privacy page)

Read `web/docs/BUILD-GUIDE.md` first. Spec source in `../Plan.md`: the whole "Visitor analytics" section, "Admin panel" (Visitors row), "Vercel readiness" (scheduled jobs, daily digest).

## You own
`src/lib/analytics/{server,ingest,ua,rollup,queries,digest}.ts` (`client.ts` already exists and is real: read it, don't edit), `src/app/api/track/route.ts`, `src/app/api/cron/rollup/route.ts`, `src/app/api/cron/digest/route.ts`, `src/app/admin/(panel)/visitors/**`, `src/components/admin/visitors/**`, `src/app/(site)/privacy/**`, `tests/unit/analytics-*.test.ts`, `tests/db/analytics.test.ts`.

## Build
**Ingest.** `POST /api/track/` (Node runtime, `force-dynamic`; the client sends `TrackPayload` from `src/lib/analytics/client.ts` with `sendBeacon`, content-type `application/json`, so read the body as text and JSON-parse it). Zod-validate (event `type` from `TrackEventType`; ids 8–64 chars; path ≤ 300 chars; `value` ≤ 1 KB; reject anything else with 204/400 and never an error page). Add on the server: country, region, city from Vercel headers (`x-vercel-ip-country`, `x-vercel-ip-country-region`, `x-vercel-ip-city`, URL-decoded; null locally), device/browser/os from the user agent with **your own small classifier in `ua.ts`** (do not add a library: `ua-parser-js` v2 is AGPL), referrer host → `source` bucket (google, facebook, instagram, whatsapp, direct, other), UTM fields. **No IP addresses and no personal data are stored.** Filter bots with `isbot` (installed) and drop their events. Respond 204 fast; do the insert inside `after()` from `next/server`. A per-visitor soft limit (ignore more than 300 events per visitor per hour, counted with a query) protects the table.

**Roll-ups.** `GET /api/cron/rollup/` (bearer `CRON_SECRET`, otherwise 401): idempotently rebuild `daily_stats` for the last 3 days (Asia/Colombo days) from `events`: metrics `visitors`, `sessions`, `page_views`, `product_views` (dimension = product id), `add_to_cart`, `chat_opened`, `chat_messages`, `booking_started`, `booking_submitted`, `whatsapp_clicks`, `source` (dimension = source bucket), `device` (dimension), `city` (dimension), `top_page` (dimension = path); use `INSERT … ON CONFLICT (date, metric, dimension) DO UPDATE`. Then delete raw events older than 90 days. `GET /api/cron/digest/` (bearer): the morning digest of yesterday's bookings and visitors: writes a bell notification (type `digest`) and, when `hasEmail()` from `@/lib/env`, sends an email through the Resend SDK to `ADMIN_ALERT_EMAIL` (never throws). Pure aggregation SQL lives in `rollup.ts`/`digest.ts` and is tested against inserted events.

**Queries (`queries.ts`)** for the Visitors page: traffic series (visitors, sessions, page views per day for 7/30 days, combining `daily_stats` with today's live events), live "on the site now" (distinct sessions with an event in the last 5 minutes), sources, the **funnel** (visit → product view → add to cart → booking started → booking submitted, distinct visitors per step and drop-off), products (views, adds to cart, bookings side by side), audience (devices, top Sri Lankan cities), chatbot (conversations, share answered instantly from FAQs vs by the model vs templates, open knowledge gaps).

**Visitors page `/admin/visitors/`** (`requireRole()` from `@/lib/auth/session`): range selector (7/30 days) in the URL, stat cards, Recharts line/area chart for traffic, horizontal bars for sources and devices, a funnel graphic with drop-off percentages, products table, cities list, chatbot panel and the live count refreshed every 30 s via a small client component calling a `GET /api/admin/live/` route you also create (`requireRole`). Every chart has a text/table alternative; empty states say "No data yet".

**Privacy page `/privacy/`** (public, indexable, short plain-English notice): what is collected (anonymous visitor and session ids, pages viewed, device type, country/city level location from the request, referrer; no IP addresses stored), what the booking and chat features store (name, phone, email, notes; chat messages), why, how long raw events are kept (90 days), that the business is in Sri Lanka and the Personal Data Protection Act applies (**do not claim compliance**; add a visible note "Draft: to be reviewed against Sri Lanka's Personal Data Protection Act before launch"), how to ask for deletion (the showroom WhatsApp/contact from `getSettings()`), third parties used (Vercel hosting, Cloudflare Turnstile, Google Maps embed, Resend email, OpenRouter for open chat questions). Use `pageMetadata` from `@/lib/seo/metadata` (seo-core; if absent at your build time use plain `Metadata`).

## Tests
Unit: UA classifier (iPhone, Android Chrome, desktop Firefox, bots), source bucketing, payload validation. DB: ingest rows written with the right derived fields (call the ingest function directly), bot events dropped, the roll-up is idempotent (run twice, same totals), 90-day purge, funnel counts distinct visitors per step, Colombo day boundaries.

## Don't
Store IP addresses or user agents verbatim; add libraries; change `client.ts`.
