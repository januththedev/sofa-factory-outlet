# Task: auth-shell (admin sign-in, session, gate, shell, notification bell)

Read `web/docs/BUILD-GUIDE.md` first. Spec sources in `../Plan.md`: "Stack" (Admin login row), "Admin panel" (modules table, Notification bell, roles), "Vercel readiness → Security".

## You own
`src/lib/auth/**` (replace the three contract stubs `session.ts`, `gate.ts`, `actions.ts`, same exports; add `config.ts`, `password.ts`, `rate-limit.ts` as needed), `src/app/api/auth/**`, `src/app/admin/layout.tsx`, `src/app/admin/login/**`, `src/app/admin/(panel)/layout.tsx`, `src/components/admin/{shell,sidebar,topbar,bell,user-menu}.tsx`, `src/app/api/admin/notifications/route.ts`, `tests/unit/auth.test.ts`, `tests/db/auth.test.ts`.

## Build
**Auth.js v5** (`next-auth@5.0.0-beta.32`, installed): Credentials provider, **JWT sessions**, `bcryptjs` (cost 12) against `admin_users` (email case-insensitive via `lower(email)`, only `active` users), `AUTH_SECRET` from env, `trustHost: true`, `pages.signIn = '/admin/login/'`, 12-hour sessions. Keep everything behind `src/lib/auth/*` so the rest of the app only sees `getSession`, `requireRole`, `signInAction`, `signOutAction`, `adminGate`. Read `node_modules/next-auth` types and the Next 16 docs before wiring; note the app uses `trailingSlash: true`, so `/api/auth/*` URLs need the slash handling checked (do not use `next-auth/react`; use server-side `auth()`/`signIn`/`signOut` only).
**Fallback if next-auth 5 beta misbehaves on Next 16:** replace it with an HMAC-SHA256-signed cookie session (`jose`, installed) plus bcrypt, behind the same exported interface, and say so in your report. Do not leave the app without working admin auth.
- `AdminSession = { userId, email, name, role }`. `getSession()` reads the session and re-checks the user is still active. `requireRole(minimum = 'any')` returns the session or `redirect('/admin/login/?next=<encoded current path when available>')`; `'owner'` also rejects staff by redirecting to `/admin/` with a flash message, or throwing a `forbidden()` page if available in Next 16 (check docs; otherwise redirect).
- `signInAction(previous, formData)`: Zod-validate email + password, small in-memory limiter (5 failures per email+IP per 15 minutes, then a generic "Too many attempts" message), constant-time-ish failure path (always run a bcrypt compare, even for unknown emails), set `lastLoginAt`, redirect to the validated `next` (only same-origin `/admin/…` paths) or `/admin/`. Generic error text ("Email or password is wrong"). `signOutAction` clears the session and redirects to `/admin/login/`.
- `adminGate(request)` (used by `src/proxy.ts`; **must not import the database**): for paths under `/admin` except `/admin/login`, redirect to `/admin/login/?next=…` when the session cookie is absent (names `authjs.session-token` and `__Secure-authjs.session-token`, or your fallback cookie); add `X-Robots-Tag: noindex, nofollow` on `/admin/*` responses; otherwise return undefined. It is only a cheap first check: every admin page and action still calls `requireRole`.
- `password.ts`: `hashPassword`, `verifyPassword`.

**Pages and shell.** `/admin/login/`: simple centred card with the logo mark, email + password (`useActionState`), error region with `aria-live`, no indexing. `src/app/admin/layout.tsx`: `robots: noindex`, no site chrome. `src/app/admin/(panel)/layout.tsx`: calls `requireRole()` and renders `AdminShell`: left **sidebar** (Dashboard `/admin/`, Products `/admin/products/`, Categories `/admin/categories/`, Bookings `/admin/bookings/` with an unread-new badge, Customers `/admin/customers/`, Knowledge `/admin/knowledge/`, Chat `/admin/chat/`, Visitors `/admin/visitors/`, Invoices `/admin/invoices/`, SEO `/admin/seo/`, Settings `/admin/settings/` shown to owners only), active state from the pathname, collapsible on mobile; **top bar** with the page area for the bell and the user menu (name, role, sign out). Admin uses the standard tokens and `src/components/ui/*`; denser than the public site, works at 360px (sidebar becomes a drawer). Pages from other agents render inside `{children}`: do not create any module pages yourself (other agents own them), but add `src/app/admin/(panel)/page.tsx` **only if it does not exist**: it belongs to admin-dashboard, so do not create it.
- **Bell** (`bell.tsx`, client): shows an unread badge; polls `GET /api/admin/notifications/` every 20 seconds (pause when the tab is hidden); a dropdown lists the latest notifications (type icon, title, relative time); clicking one marks it read (`POST` with the id) and navigates to its `link`; "Mark all read"; optional sound toggle and browser notifications (ask permission only on a click; remember the choice in localStorage). The route (`force-dynamic`, `requireRole('any')`) returns `{ unread, items }` using `listNotifications`/`unreadNotificationCount` and accepts `POST { ids?: number[] }` to mark read (`markNotificationsRead`), validated with Zod. Also export `unreadBookingsCount()` helper for the sidebar badge (count notifications of type `booking` that are unread).

## Tests
`tests/unit/auth.test.ts`: password hash/verify, `next` URL sanitising (rejects `//evil.com`, `https://…`, non-admin paths), `adminGate` with a mocked `NextRequest` (redirects without cookie, passes with it, sets noindex header, never touches `/admin/login`). `tests/db/auth.test.ts`: credential check against a seeded owner (seed uses `OWNER_EMAIL`/`OWNER_PASSWORD` from the vitest env: `owner@test.local` / `test-password-123`), wrong password, inactive user, case-insensitive email, notifications route logic (extract the handler logic into a testable function).

## Don't
Create module pages; import the database in `gate.ts`; log passwords or tokens; reveal whether an email exists.
