# Task: admin-products (product editor, upload pipeline, categories, colour rules, CSV import)

Read `web/docs/BUILD-GUIDE.md` first. Spec sources in `../Plan.md`: "Automated product pipeline" (what happens on Save, the product list fills itself), "Admin panel" (Products and Categories rows), "SEO → 10. Measuring it" (SEO checklist in the product editor), "SEO and migration".

## You own
`src/app/admin/(panel)/products/**`, `src/app/admin/(panel)/categories/**`, `src/components/admin/products/**`, `src/lib/admin/products.ts` (server-side save logic), `src/lib/admin/seo-checklist.ts`, `src/lib/catalogue/csv.ts`, `src/app/api/admin/upload/route.ts`, `tests/unit/{seo-checklist,csv}.test.ts`, `tests/db/admin-products.test.ts`.

## Build (every page, action and route starts with `requireRole()` from `@/lib/auth/session`; delete and category/colour-rule edits are owner-only, product editing is staff + owner)
**List `/admin/products/`**: table (photo thumbnail, name, category, status badge, price or "on request", featured star, SEO checklist dot green/amber/red, updated), search, filters by status/category, bulk actions (publish, hide, delete [owner]), "New product" and "Import CSV" buttons. Review notes from `products.review_notes` appear as badges (borrowed-images, supplier-photos, photo-mismatch, no-description, derived-facets, size-options, price-on-request, no-dimensions) with a short explanation tooltip.

**Editor `/admin/products/new/` and `/admin/products/[id]/`** (React Hook Form + Zod): name; slug (auto from the name, editable; a change creates a 301 from the old URL); category; short + long description (Markdown textarea with live preview); selling points; material, shape, seats, tags; dimensions (width/depth/height/seat height/note in cm); price in rupees or "Price on request", "From" price flag, compare-at price; status draft/published/hidden; featured; SEO title/description with live character counters and a Google-style preview; noindex; **colour variants**: add/remove/reorder, each with a colour name, hex via picker **and an eyedropper on the variant's photo** (click the photo to sample; use a canvas `getImageData`), family/tone/warmth auto-classified with `classifyHex` and overridable, in-stock; **drag-and-drop photos per variant** (multiple files, reorder, alt text, delete, the "flag" chips for borrowed/licence photos) uploading through `POST /api/admin/upload/` which accepts `multipart/form-data`, validates with Zod (type jpeg/png/webp/avif, ≤ 12 MB, ≤ 12 files), runs `processImage` from `@/lib/images/process` (4 widths × AVIF/WebP via the storage adapter, `keyPrefix: products/<productId>`), and returns the resulting `ImageRef`s. Unsaved new products upload under a temporary prefix then keep the same refs on save.
- **Save pipeline** in `src/lib/admin/products.ts` (`saveProduct(input, userId)` in one transaction): normalise and validate; rebuild `search_text` with `buildSearchText` (`@/lib/catalogue/search-text`); set `published_at` on first publish; when the slug changes or the product becomes hidden/draft or is deleted, upsert rows in `redirects` (old URL → the category hub with status 301; deleted → status 410; when a product is published again delete its hub redirect; avoid redirect chains by repointing existing rows whose target was the old slug); then **after the transaction** call `revalidateCatalogue()` and `revalidateRedirects()` from `@/lib/revalidate`. The "New" label is automatic (30 days) so nothing to store. Write actions in `actions.ts` with `'use server'`, returning `{ ok, error?, fieldErrors? }`.
- **SEO checklist**: replace the contract stub `src/lib/admin/seo-checklist.ts` (`evaluateSeoChecklist` and its types stay exactly as declared there): five checks `meta` (title 30–60 characters, using the name when no SEO title is set, and description 70–160), `photos` (at least 4, all with alt text), `copy` (description of 150+ words), `price` (set), `guide` (a `guide:<slug>` tag); green = all 5, amber = 3 or 4, red = fewer than 3. It is pure and also used by the product list, the editor and the SEO admin page.

**Categories `/admin/categories/`** (owner can edit, staff view): tree of categories and hubs, edit name, intro, tips, SEO fields, sort order, image upload (same pipeline, `keyPrefix: categories/<slug>`), toggle hub filters; a "Colour rules" tab managing `colour_pairings` (add/remove/edit weight and reason verb) and `category_complements`; changes call `revalidateCatalogue()`.

**CSV import** (`src/lib/catalogue/csv.ts` with `papaparse`): one row per product, columns `name, category, price, status, material, shape, seats, tags, description, colour_1_name, colour_1_hex, colour_1_photo_urls, colour_2_name, …` (one column group per colour); a downloadable template; a preview step that validates every row (Zod) with line-by-line errors before anything is written; photo URLs are fetched server-side only from `https` URLs and pushed through `processImage` (skip rows whose photos fail with a clear message). Pure parsing/validation lives in `csv.ts` and is unit-tested.

## Tests
`seo-checklist` and `csv` unit tests (valid, invalid, edge columns, colour group parsing, BOM, quoted commas); `tests/db/admin-products.test.ts`: create/update products, slug change writes a 301 and avoids chains, hiding writes the hub redirect, republishing removes it, deleting writes a 410, publishing sets `published_at` once, `search_text` rebuilt.

## Don't
Touch `src/lib/db/schema`; write directly to the `redirects` table from components; skip `requireRole`.
