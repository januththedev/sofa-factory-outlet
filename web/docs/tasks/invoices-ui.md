# Task: invoices-ui (admin invoices, quotations, reports)

Read `web/docs/BUILD-GUIDE.md` first. Spec source in `../Plan.md`: the whole "Invoices" section (steps 1–7 and extras), "Admin panel" (Invoices and Customers rows).

## You own
`src/app/admin/(panel)/invoices/**`, `src/components/admin/invoices/**`, `src/lib/admin/invoices.ts` (thin helpers, formatting, CSV), `tests/unit/invoice-ui.test.ts`.

## Build (every page and action starts with `requireRole()` from `@/lib/auth/session`; cancel and settings-affecting actions are owner-only, everything else staff + owner)
All data and rules come from the contract in `src/lib/invoices/api.ts` (`computeTotals`, `saveInvoiceDraft`, `issueInvoice`, `recordPayment`, `cancelInvoice`, `convertQuotationToInvoice`, `listInvoices`, `getInvoice`, `revenueReport`, `renderInvoicePdf`, `createShareLink`, `createInvoiceFromBooking` and the types). Another agent implements it behind the same signatures: never re-implement totals, numbering or status rules; catch errors and show friendly messages. Money is integer minor units (`formatLkr(minor, { decimals: true })` gives "Rs. 1,250,000.00"; the UI takes rupees and converts).

**List `/admin/invoices/`**: tabs Invoices / Quotations / Reports; table (number or "Draft", customer, source badge website/walk-in, status badge, total, paid, balance, issued date), filters (status, source, date range), search (number, customer, phone), pagination via URL params, totals strip for the filtered set, "New invoice" and "New quotation" buttons, overdue/outstanding highlighted. Server components read `searchParams` (a Promise).

**Builder `/admin/invoices/new/` and `/admin/invoices/[id]/edit/`** (drafts only; `params` is a Promise): 1. **Start**: from a booking (`?booking=<id>` calls `createInvoiceFromBooking` and redirects to the edit page) or from scratch for a walk-in; 2. **Customer**: type-ahead search of customers by phone or name (a server action querying `customers`; also created by "Add new customer": name, phone normalised with `normaliseLkPhone`, address, optional email; an existing phone attaches the existing customer); 3. **Line items**: catalogue type-ahead (server action searching published products by name, returning variants), choose the colour variant, then quantity, unit price (defaults to the product price, editable; "price on request" products start at 0 and are flagged), optional line discount; **custom lines** for extras such as "Delivery to Kandy" or "Extra cushions"; 4. **Totals** live in the browser with `computeTotals` (a pure function, safe to import in a client component): subtotal, discount (amount or %), delivery charge, tax (off by default; shows the configured label and rate from `settings.invoice` only when `taxEnabled`), grand total, advance paid and balance due; 5. notes, terms (prefilled from settings), delivery date; **Save draft** (`saveInvoiceDraft`) and **Issue** (`issueInvoice`, then redirect to the detail page). Validate with Zod on the server too. Autosave is not needed; warn on leaving with unsaved changes.

**Detail `/admin/invoices/[id]/`**: the printable invoice page (logo from `/brand/logo.png`, business and bank details from `getSettings()`, customer, items table, totals, delivery date, warranty and terms, signature lines), a status header with actions: **Print** (A4 print stylesheet in a `<style>` tag; hide the admin chrome with `@media print` and `@page { size: A4; margin: 14mm }`; a `window.print()` button), **Download PDF** (`/api/invoices/<id>/pdf/`), **Share on WhatsApp** (calls `createShareLink`, builds a `wa.me` link to the customer's WhatsApp/phone with a prefilled message and the PDF link), **Record payment** (dialog: amount, method cash/bank transfer/card, date, reference, note; `recordPayment`, shows the new balance), payment history, **Cancel** (owner-only, confirm dialog; `cancelInvoice`), for quotations **Convert to invoice** (`convertQuotationToInvoice`) and a badge when converted. When the invoice is marked Paid, offer the one-tap WhatsApp Google-review request (prefilled `wa.me` text with `settings.business.map.googleReviewUrl` when set). The invoice number, status and the originating booking link are always visible.

**Reports tab**: monthly revenue (invoiced, paid, website vs walk-in) as a table and a Recharts bar chart (client component, text alternative), the outstanding balances list, "Export CSV" route handlers (`/admin/invoices/export/` for the filtered list and `/admin/invoices/reports/export/` for the report) with `requireRole`, properly escaped CSV (`src/lib/admin/invoices.ts` exports a pure `toCsv(rows, columns)` that is unit-tested).

## Tests
`tests/unit/invoice-ui.test.ts`: `toCsv` (quotes, commas, newlines, BOM for Excel, number formatting), rupee↔minor conversion (decimals, rounding, rejecting negatives), WhatsApp message/link building, status badge mapping, line-form reducers if you extract them.

## Don't
Reimplement `computeTotals` or any invoice rules; skip `requireRole`; add dependencies.
